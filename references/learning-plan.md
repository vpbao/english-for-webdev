# Learning Plan — Detailed Instructions

## Before Creating the Plan

Ask the user:
- How many hours per week can they dedicate?
- Any upcoming deadlines? (interview date, project with English-speaking team, etc.)
- Which area feels most urgent?

If the user already provided enough context, do not ask again. Build the plan from what is known and state any assumption briefly.

## Plan Structure

Create a plan with 3 phases. If there's a deadline (e.g., interview in 1 month), compress the phases to fit the timeline.

### Phase 1: Foundation (Weeks 1-4)
- Essential developer vocabulary (200 most common words in docs, PRs, and meetings)
- Basic sentence patterns for developer communication
- Reading simple documentation and README files
- Writing basic commit messages and short comments

### Phase 2: Professional Communication (Weeks 5-8)
- Writing PR descriptions and code review comments
- Composing Slack messages and emails to teammates
- Understanding and participating in daily standups
- Reading technical blog posts and changelogs

### Phase 3: Advanced & Interview (Weeks 9-12)
- Explaining technical decisions and architecture
- Behavioral interview questions (STAR method in English)
- Technical interview communication (thinking out loud, clarifying questions)
- Writing technical documentation and RFCs
- Presenting demos and sprint reviews

## Weekly Breakdown Template

Each week should include:
- **Vocabulary set** (15-20 words/phrases with examples from real dev contexts)
- **Reading assignment** (a real doc page, blog post, or GitHub issue)
- **Writing exercise** (a realistic task like "write a PR description for this feature")
- **Speaking prompt** (record yourself explaining something technical)
- **Checkpoint** (self-assessment quiz)

Include checkboxes so the user can track progress.

## Output Format

If the user only wants guidance, answer in chat. If they want a reusable plan, create a polished structured deliverable. Include:
- Weekly schedule with daily tasks
- Vocabulary lists with IPA, Vietnamese translation, example sentences
- XP milestones and level progression targets
- Spaced repetition review schedule
- Skill radar starting scores and target scores

## Quality Bar

A publish-worthy plan should:
- reflect the learner's deadline, available time, and weakest skill
- sequence speaking practice from week 1 instead of postponing it
- include both work-English and interview-English when relevant
- convert goals into concrete weekly behaviors, not just topic lists
